# EC-04 — Concurrent apply voucher vs xoá item (optimistic lock, SRS §8)

**SRS gốc:** "Two concurrent requests: one applies voucher, other removes the last eligible item
from cart." Kỳ vọng: optimistic locking trên cart entity; request thứ 2 trigger revalidation; nếu
voucher không còn hợp lệ thì gỡ; **cả 2 operation cùng thành công, không có state không nhất quán**.

**Priority:** Must | **Annotation trong SRS gốc:** not done

**Kết luận: PARTIALLY DONE** — xác nhận bằng đọc code trực tiếp (không dựa vào audit cũ), theo
quyết định của Cealus (2026-07-21): **chỉ document hiện trạng, chưa viết test mới / chưa fix**, vì
fix đúng 100% SRS (đảm bảo "cả 2 cùng thành công") là quyết định kiến trúc cần bàn riêng (có thể cần
version column thật trên Cart, hoặc mở rộng lock để bao phủ cả native Medusa cart-mutation
workflow), còn viết test race thật (2 request đồng thời) có rủi ro flaky vì không có cách chèn
điểm dừng giữa 2 bước của workflow từ bên ngoài mà không đụng production code.

chữ — khách phải retry request apply. Đây là gap **business behavior**, khác với claim "resolved" cũ
trong memory (đã sửa lại, xem [[ratelimit-fix-in-progress-separate-agent]]).
