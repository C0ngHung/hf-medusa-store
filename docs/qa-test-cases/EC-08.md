# EC-08 — Thêm suggested item vượt ngưỡng tier promotion mới (SRS §8)

**SRS gốc:** "Cart has voucher applied. Customer adds a suggested item that triggers a price
recalculation pushing total past a new promotion tier (e.g., 'Spend 5M get extra 5% off')." Kỳ vọng:
tier promotion mới áp dụng như item-level discount → voucher tính lại trên post-promo subtotal MỚI →
global cap re-check → khách hưởng cascading discount tới đúng mức cap cho phép.

**Priority:** Should | **Annotation trong SRS gốc:** not done

**Kết luận: ĐÚNG — annotation "not done" trong SRS gốc SAI, cơ chế thực ra ĐÃ hoạt động đúng.**
Trước phiên này, kịch bản này **chỉ có demo thủ công** (`src/scripts/seed-tier-promo.ts`), chưa có
test tự động nào ghép đủ: tier-promotion thật + voucher + cascading recompute + global cap. Đã viết
1 test integration mới hoàn toàn, đi qua đúng đường production thật (không gọi `revalidateVoucherWorkflow`
bằng tay — chờ `cart.updated` → subscriber tự trigger, dùng `waitFor` polling).

**Diễn biến khi debug (đáng ghi lại):**

- Lần chạy 1: dùng `addToCartWorkflow` cho CẢ 2 item (Racket + String) → bị lỗi `Failed to acquire
lock for key voucher:cart:...` vì item Racket đầu tiên cũng emit `cart.updated` → subscriber tự
  chạy `revalidateVoucherWorkflow` bất đồng bộ → race với lệnh `applyVoucherWorkflow` gọi ngay sau đó
  (cùng tranh 1 lock key). Sửa: tạo item Racket bằng raw `cartModuleService.createCarts` (không emit
  event), chỉ dùng `addToCartWorkflow` thật cho item String (đúng cái cần test).
- Lần chạy 2: hết lỗi lock, nhưng assertion fail vì `voucherSnapshot` là `undefined` — do lỗi trong
  chính test: quên thêm `"metadata"` vào tham số `select` khi đọc lại cart (Medusa's `select` là
  allowlist nghiêm ngặt). Sau khi debug bằng cách dump toàn bộ cart, xác nhận tier promotion **đã áp
  dụng đúng 100%** (200,000 trên dòng Racket + 75,000 trên dòng String = 275,000, đúng 5% của
  5,500,000) — lỗi chỉ nằm ở test, không phải ở code sản phẩm.
- Lần chạy 3 (sau khi sửa `select`): **pass**.
